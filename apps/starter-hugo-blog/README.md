# starter-hugo-blog

A **Jamstack** starter: [Hugo](https://gohugo.io) renders a static blog from markdown files and a
small sidecar Hono server hosts the Decap CMS admin. The two processes share the same
`content/posts/` directory on disk.

## Stack

- **Site (build-time):** Hugo — Go-based SSG, sub-second builds, Go template layouts
- **Admin (runtime):** Hono + `@hono/node-server` + LaikaCMS embedded preset
- Decap CMS shell loaded at runtime via `decapAdminHtml()`

## Prerequisites

Hugo must be installed separately (it is a Go binary, not an npm package):

```bash
# macOS
brew install hugo

# Debian/Ubuntu
sudo apt install hugo

# Windows (Scoop)
scoop install hugo
```

Verify: `hugo version` — requires Hugo v0.120+.

## Quick start

```bash
pnpm install
pnpm --filter @laikacms/starter-hugo-blog dev
```

`pnpm dev` runs both processes via `concurrently`:

- Hugo dev server: <http://localhost:1313> (blog, live-reload)
- Admin server: <http://localhost:3001/admin> (Decap CMS)

Edit a post in the admin → file saved to `content/posts/` → Hugo rebuilds → refresh `:1313`.

## Project layout

```
hugo.toml             # Hugo config (baseURL, permalinks, goldmark options)
layouts/
  index.html          # Homepage: lists all posts from the posts/ section
  _default/
    baseof.html       # Base HTML skeleton
    single.html       # Individual post page
content/
  posts/
    hello-world.md    # Sample post (frontmatter + body)
server/
  admin.ts            # Sidecar Hono server — Decap admin + JSON:API
static/
  uploads/            # Media upload target (served by Hugo at /uploads/)
```

## Why two separate servers?

Hugo is a static site generator — it has no runtime HTTP server of its own (only a dev server
`hugo server` for local preview). `createEmbeddedLaika` requires a persistent Node.js process to
host the Decap JSON:API. Running them on separate ports is the simplest approach:

| Server        | Port | Purpose                                        |
| ------------- | ---- | ---------------------------------------------- |
| `hugo server` | 1313 | Serves the generated static site + live reload |
| Hono admin    | 3001 | Decap CMS admin UI + LaikaCMS JSON:API         |

In production you'd run only `hugo build` (no admin) and serve the `_site/` output from a CDN. The
admin lives on a separate deployment (or is removed entirely and replaced by a hosted gateway).

## Hugo content conventions

Hugo posts live in `content/posts/` with YAML frontmatter:

```yaml
---
title: "My Post"
date: 2024-01-15T00:00:00Z
description: "Optional summary"
---

Post body written in **Markdown** — Hugo renders it as HTML.
```

Decap's `datetime` widget produces ISO 8601 dates (`2024-01-15T00:00:00.000Z`). Hugo parses these
without issue.

Hugo's `draft: true` flag is **not** included in the default Decap collection config. Posts without
`draft: true` are published by default. Add the field if you need draft support:

```ts
import { createEmbeddedLaika, minimalBlogConfig } from '@laikacms/decap-integrations/embedded';

const baseConfig = minimalBlogConfig({ mediaFolder: 'static/uploads' });
const collections = baseConfig.collections as Array<Record<string, unknown>>;

createEmbeddedLaika({
  decapConfig: {
    ...baseConfig,
    collections: collections.map(col => ({
      ...col,
      fields: [
        ...(col.fields as unknown[]),
        { label: 'Draft', name: 'draft', widget: 'boolean', default: false, required: false },
      ],
    })),
  },
});
```

## `static/` vs `public/` in Hugo

Hugo terminology:

| Directory | Purpose                                                          |
| --------- | ---------------------------------------------------------------- |
| `static/` | Source static files — copied verbatim into the build output      |
| `public/` | Build output (generated by `hugo build`) — deploy this directory |
| `_site/`  | Build output when `--destination _site` is passed                |

Files in `static/uploads/` are served at `/uploads/` during `hugo server` and end up in
`public/uploads/` (or `_site/uploads/`) after `hugo build`. That's why `minimalBlogConfig` receives
`{ mediaFolder: 'static/uploads' }` — Decap writes there, Hugo serves it.

## `media_folder` mismatch between admin and site (doc gap)

Decap admin's image picker shows images at their `public_folder` URL (`/uploads/foo.png`). The admin
server is on port 3001, but the images are served by Hugo on port 1313. Image previews inside the
admin UI may not load correctly in dev. The images are correctly referenced in the published
markdown and will render properly on the Hugo site. In production (CDN-hosted admin), both the admin
and site share the same origin and this issue disappears.
